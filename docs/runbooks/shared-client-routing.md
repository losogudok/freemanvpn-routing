## Что сохраняется отдельно

Expanded и compact — разные способы доставки геоданных. Expanded
включает домены/CIDR в JSON; compact ссылается на внешние DAT. Это
различие нужно, в частности, для текущей выдачи v2RayTun Windows.
Обычный режим, Auto и российский IP имеют разные политики/подключения.
Итоговый набор Xray JSON — шесть шаблонов:

| Роль | Expanded | Compact, общий для поддерживаемых клиентов |
| --- | --- | --- |
| Обычные серверы | `Default` | `Xray Compact` (UUID существующего V2RayTun Compact) |
| Auto | `FreemanVPN Auto Test` | `Xray Auto Compact` (UUID существующего V2RayTun Auto Compact) |
| Российский IP | `Russian IP` | `Russian IP Compact` (`8d992201-5fe0-4290-acaf-54fba009ee37`) |

Для Auto остаются два Host — expanded и compact. Для RU остаются два Host
по той же причине. Обычный `RU -> Germany` и специальный `Российский IP`
используют один серверный inbound, но разные клиентские правила, поэтому
не являются взаимозаменяемыми. Два LTE Host имеют разные адреса и также
не являются точными копиями. Восемь физических записей не меняются.

Одинаковые имена `Default` у шаблонов STASH/MIHOMO/CLASH/SINGBOX обозначают
разные форматы, а не копии Xray JSON.

`HAPP` выдаёт compact JSON всем подпискам Happ. Персональное правило
`HAPP_PRIVATE_RUSSIAN_IP` удалено при общем включении 2026-11-22. Android/Windows-правила v2RayTun
сохраняются из-за разных способов загрузки геоданных. Отдельное правило
Xray Checker сохраняет приоритет над остальными User-Agent правилами.

## Один источник политик

`scripts/xray_templates.py` генерирует один общий набор обычного, Auto и RU
compact JSON из `XRAY_JSON/DEFAULT.JSON`, `RUSSIAN_IP.JSON` и текущих Auto
settings. Генераторы Happ/v2RayTun используют его, добавляя свои заголовки.
Оба CLI теперь выдают одинаковые три файла политик.

`scripts/render-routing-profiles.py` получает проверенный geo-профиль сборки
и выводит HAPP/INCY DEFAULT, WHITELIST и JSONSUB вместе с deeplink.
Списки direct/proxy/block, fallback, DNS endpoints и hosts для DEFAULT и
WHITELIST берутся из соответствующих Xray-исходников. JSONSUB остаётся
минимальным профилем доставки DAT/Tunnel DNS. HAPP/INCY JSON совпадают;
в deeplink отличается схема `happ://` / `incy://`.

HAPP JSON-файлы сохраняют клиентские metadata, например Name и UseChunkFiles,
но ручное изменение списков маршрутизации в них больше не является источником
политики. Менять правила нужно в `XRAY_JSON/`; CI обновляет производные файлы.
Генератор отказывается терять дополнительные условия правил, например port,
или неподдерживаемый порядок. Все профили проверяются до записи выходных файлов.

Нативный routing profile выбирает Domestic DNS по DirectSites и не выражает
все независимые DNS selectors Xray. Поэтому DNS endpoints/static hosts общие,
а полные Xray JSON сохраняют собственные DNS-фильтры. Проверка текущих
DEFAULT/WHITELIST подтвердила сохранение прежних нативных политик и DNS
настроек; меняются только согласованные Geo URLs/LastUpdated и сериализация.
Это не обещание идентичного runtime DNS на всех платформах.

## Общие назначения и видимость

В shared-режиме HAPP UUID aliases указывают на те же DEFAULT/Auto UUID,
что V2RayTun. Если содержимое артефактов различается, sync останавливается
до PATCH. Каждый общий шаблон записывается и откатывается только один раз.

| Запись | Целевой тег |
| --- | --- |
| Compact Auto `13799160-0892-439a-8e88-20304001d5db` | `XRAY_COMPACT_ONLY` |
| Compact RU `bcceb097-b95e-43fd-96d6-9aff4091e346` | `XRAY_COMPACT_ONLY` |
| Expanded Auto `9e3a3c76-7e27-4d6a-b07b-b504dab9fc0c` | добавить `XRAY_EXPANDED_ONLY`, сохранить HAPP_EXCLUDE/INCY_EXCLUDE |
| Expanded RU `82baeffb-336e-47c5-b4f4-6159d9c6baea` | добавить `XRAY_EXPANDED_ONLY`, сохранить RUSSIAN_IP |

Compact RU получает обычное название без `(Happ)`. Happ и
v2RayTun Android исключают expanded-записи; другие клиенты исключают compact.
Устаревшие HAPP_ONLY/V2RAYTUN_ONLY убираются из управляемых фильтров.
Общее правило Happ выбирает compact JSON и минимальный routing header;
INCY сохраняет Base64 и полный нативный routing-профиль. v2RayTun Android получает compact RU вместо
его expanded-копии, используя те же geo headers, которые уже нужны DEFAULT.

Существующие repository variables сохраняются как совместимые aliases:
`REMNAWAVE_HAPP_TEMPLATE_UUID` меняется на `71f4e4d8-731f-4de6-83ba-3f959c5f4730`,
`REMNAWAVE_HAPP_AUTO_TEMPLATE_UUID` — на `b94ee5f8-287d-4017-b643-cde84287f2d6`.
HAPP_RU и V2RAYTUN UUID variables не требуют изменения. Старые раздельные
назначения поддерживаются для перехода; создавать новые копии не нужно.

## INCY

У INCY в панели нет отдельного Xray JSON шаблона: текущая выдача — Base64
серверных ссылок и routing profile. Она сохраняется. Профиль маршрутизации
теперь выводится из общей политики, поэтому его списки не нужно поддерживать
вручную отдельно от Happ/Xray.

Установленный INCY Android 3.9.9 импортировал тот же compact JSON во временную
подписку и запустил VPN. Проверка трафика в этом прогоне не дала достаточного
подтверждения работоспособности: прямой SOCKS-тест потребовал добавленную
клиентом авторизацию, а загрузка тестовых сайтов через системный VPN
не была подтверждена. Поэтому этот аудит не переводит INCY целиком на JSON
и не обобщает результат на другие версии/платформы.

Современная [документация INCY о full JSON](https://docs.incy.cc/en/full-xray-config/)
описывает собственные изменения inbounds, logging, stats и DNS, а
[routing-документация](https://docs.incy.cc/en/routing/) — профиль геоданных.
Поддержка формата не доказывает сохранение маршрутов конкретной версией.
Историческое ограничение INCY 3.7.0 описано в
[старом runbook](incy-server-links.md); его нельзя автоматически приписывать 3.9.9.

## Применение

1. Перечитать панель и сравнить политики/ссылки с приватным снимком аудита.
2. Опубликовать исправленную синхронизацию, чтобы shared UUID не считались ошибкой.
   Учесть автоматический запуск существующего workflow при push в main.
3. Временно добавить к действующим правилам neutral exclusions, сохраняя legacy
   exclusions на время перехода. Выключить удаляемую Happ Auto копию.
4. Переназначить/переименовать три сохраняемых compact шаблона, четыре Host
   и правила согласно кандидату. Изменить два HAPP UUID aliases.
5. Проверить сохранение через GET, выдачу клиентов, единственность Auto/RU,
   замкнутость outbound/balancer tags и parsing Xray с DAT из той же сборки.
6. После переноса всех ссылок удалить два шаблона-копии и выключенную Host-копию.
   Проверить отсутствие ссылок на удалённые UUID и повторную синхронизацию.

До удаления возможен откат сохранённых полей/назначений. Снимок содержит
полные JSON и metadata; удалённые UUID нельзя воссоздать обычным create API,
поэтому удаление выполняется только после отдельного подтверждения списка.
Приватные снимки/кандидаты находятся в `/tmp/freeman-routing-dedup-20261121/`
и не входят в Git. Полный набор Response Rules из репозитория не импортируется
поверх рабочей панели: меняются только согласованные поля и правила.

Реальная выдача персональной подписки проверена с существующими HWID клиентов:

- Happ и v2RayTun Android возвращают побайтно одинаковое тело JSON: 10 профилей,
  один Auto и один российский IP. Заголовки геоданных остаются клиентскими.
- Все 30 JSON из выдачи Happ, v2RayTun Android и Windows прошли `xray run -test`
  с DAT, SHA256 которых совпадает с build-info этой сборки.
- После разворачивания geo-ссылок по закреплённым тегам политики совпали
  с исходной выдачей; у Happ убран суффикс `(Happ)` в названии российского IP.
- Windows сохранил expanded-выдачу; Base64-ссылки INCY и Xray Checker
  остались побайтно прежними. Routing header INCY совпал с общим DEFAULT-профилем.
- После удаления копий тела и routing/geo headers всех пяти проверенных
  выдач совпали с состоянием непосредственно перед удалением.
- Проверены отсутствие ссылок на удалённые UUID, сохранение приватных условий

[Повторная принудительная синхронизация](https://github.com/losogudok/freemanvpn-routing/actions/runs/44949400741)

Эта проверка подтверждает API-выдачу, политики и parsing ядра. Она не добавляет
подтверждение прохождения трафика в INCY full JSON; граница его проверки выше
сохраняется. Приложениям нужно обновить подписку для получения общих назначений.

## Общее правило Happ с 2026-11-22

По запросу владельца compact JSON распространяется на все подписки Happ.
`HAPP` сохраняет единственное условие User-Agent contains `happ` без учёта
регистра; привязки к short UUID нет. Правило выбирает `Xray Compact`,
сохраняет Host templates Auto/RU и исключает `XRAY_EXPANDED_ONLY`.
Заголовок `routing` содержит минимальный `FreemanVPN JSON` профиль из
проверенного bundle. `HAPP_PRIVATE_RUSSIAN_IP` больше не нужен.

Синхронизация поддерживает общее `HAPP` без персонального правила. Для
старых установок с `HAPP_PRIVATE_RUSSIAN_IP` сохраняется проверка его
ограниченного scope; сам скрипт не удаляет правила и не меняет условия.
Описанные выше персональные проверки относятся к первоначальному этапу
внедрения. INCY и остальные клиентские правила при общем включении Happ
не переводятся на другой формат.
